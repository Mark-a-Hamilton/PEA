# **PEA Modules Overview**

The Privilege‑Escalation‑Analyser (PEA) uses a modular analysis system to interpret and evaluate the raw output generated by LinPEAS. Each module is responsible for analysing a specific subsection of the LinPEAS output, extracting relevant indicators, and mapping them to the knowledge base and privilege‑escalation principles.

Modules allow PEA to remain structured, predictable, and easily extensible as enumeration techniques evolve.

---

## **Module Naming Conventions**

PEA currently supports **LinPEAS output only**, and all existing modules follow the naming prefix:

```
lpa-
```

This prefix identifies the module as part of the **LinPEAS Analysis Pack**, ensuring clarity when multiple platform engines are introduced in the future.

Examples:

- `lpa-services.py`
- `lpa-packages.py`
- `lpa-sudo.py`
- `lpa-capabilities.py`

Each module is tightly coupled to a specific LinPEAS subsection and is loaded automatically based on the active profile.

---

## **Future Platform Support**

Although PEA currently focuses exclusively on LinPEAS, the engine is designed to scale with the evolution of the **PEASS‑NG** project.

When **WinPEAS** support is introduced, modules will follow the prefix:

```
wpa-
```

This will clearly distinguish Windows‑specific analysis modules from Linux‑specific ones.

Examples (future):

- `wpa-services.py`
- `wpa-registry.py`
- `wpa-uac.py`
- `wpa-unquoted.py`

This naming strategy ensures:

- clean separation of platform logic  
- predictable module routing  
- easy maintenance  
- straightforward expansion into MacPEAS or other future enumeration tools  

---

## **How Modules Work**

Each module performs four core tasks:

1. **Section Extraction**  
   The module receives a subsection of LinPEAS output defined by the active profile.

2. **Data Interpretation**  
   The module parses the subsection, extracting relevant indicators, values, or misconfigurations.

3. **Knowledge‑Base Mapping**  
   Findings are matched against the PEA knowledge base to determine:
   - severity  
   - exploitability  
   - remediation guidance  
   - PrivEsc principle alignment  

4. **Report Contribution**  
   The module returns structured results that are merged into the final PEA analysis report.

This modular approach ensures that each part of the LinPEAS output is analysed consistently and independently.

---

## **Extending Modules**

New modules can be added by:

- creating a new file with the appropriate prefix (`lpa-` or future `wpa-`)  
- defining the subsection markers in the profile  
- implementing the analysis logic  
- updating the knowledge base if required  

PEA automatically loads modules based on the active profile, making extension straightforward and predictable.

---

## **Summary**

PEA modules provide the analytical backbone of the Privilege‑Escalation‑Analyser.  
The current `lpa-` module set supports LinPEAS output, while the architecture is ready for future `wpa-` modules to support WinPEAS and additional PEASS‑NG tooling.

This modular design ensures PEA remains scalable, maintainable, and adaptable as privilege‑escalation enumeration continues to evolve.
